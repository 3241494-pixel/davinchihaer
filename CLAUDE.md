# CLAUDE.md

## Проект
 
Сайт бренда **Da Vinchi Hair** — продажа волос и систем для ленточного наращивания Tape-In.
База бизнеса: **Тбилиси, Грузия**.
 
Модель: **витрина + заявка**. Корзины, checkout и онлайн-оплаты НЕТ и не планируется.
 
**У сайта три воронки, не одна:**
1. **Розница** — женщины 25–45 покупают волосы для себя. Заявка на подбор цвета и длины.
2. **Опт** — мастера и салоны. Страница `/wholesale`, прайс НЕ публикуется, высылается по заявке.
3. **Обучение** — `/academy`: видеокурс онлайн и очный курс в Тбилиси. Заявка → оплата вручную вне сайта → доступ.
Все три ведут в один Telegram-бот, но в разные темы супергруппы.
 
Языки: `ru` (основной, эталон контента), `en`, `ka` (грузинский — локальный рынок).
Валюта: **только евро**, без конвертера.
 
## Стек
 
- Next.js 15, App Router, React Server Components по умолчанию
- TypeScript, `strict: true`, без `any`
- Tailwind CSS v4, токены в `@theme` в `src/app/globals.css`
- next-intl для локализации
- react-hook-form + zod для форм
- MDX для контентных страниц (`@next/mdx`)
- Vitest для юнит-тестов контент-слоя
- Хостинг Vercel

```
src/

  components/ui/          примитивы дизайн-системы
  components/sections/    секции страниц
  components/catalog/     карточки, фильтры, галерея
  components/forms/       LeadForm и его три варианта
  lib/content/            ЕДИНСТВЕННАЯ точка доступа к контенту
    types.ts              типы домена
    products.ts           getProducts, getProduct, filterProducts, getColors
    source/               адаптер источника (сейчас файлы, потом CMS)
  lib/actions/            server actions (отправка заявок)
  lib/telegram.ts         отправка в бота, роутинг по темам
  config/site.ts          контакты, соцсети, адрес — единственный источник
  i18n/                   конфиг и словари
content/
  products/*.json
  colors.json
  pages/*.mdx
  source/                 исходные тексты клиента, НЕ трогать
messages/
  ru.json  en.json  ka.json
```
 
**Правило №1:** компоненты и страницы НИКОГДА не читают файлы из `content/` напрямую и не импортируют JSON. Только через функции из `lib/content`. Источник данных должен заменяться на CMS без изменения ни одного компонента.
 
**Правило №2:** контакты, ссылки на соцсети, адрес, телефон — только из `config/site.ts`. Хардкод в JSX запрещён.
 
## Деньги
 
- Цены хранятся **целым числом в евроцентах** (`price: 19990`). Никаких `float` — `19.99 * 3` даёт `59.97000000000001`.
- Форматирование только на выводе, через `Intl.NumberFormat` с локалью и `currency: 'EUR'`.
- Цена принадлежит варианту (длина + оттенок), а не товару.

## Изображения

Реестр — `src/content/images.ts`, размеры и blur-заглушки — `src/lib/images/blur-data.json`. Вставка только через `<Media path="..." />` (`src/components/ui/Media.tsx`), прямой `next/image` в страницах и секциях не использовать.

- Файлы с `usage: ['gallery-only']` (сняты на зелёном сатине, конфликтует с монохромом) — **не ставить в каталог и на главную**, только на `/gallery`.
- `tapeClassicRolls` — временный hero (самый графичный кадр на белом фоне, без модели). Заменить, как только будет фото с моделью или «до/после».

## Заявки
 
Три типа: `retail` | `wholesale` | `training`. Общее ядро полей (имя, контакт, канал связи, комментарий, согласие на ПД) + свои поля у каждого типа.
 
Отправка в Telegram Bot API, темы супергруппы выбираются по типу заявки через `message_thread_id`. В каждое сообщение добавляется служебный блок: страница-источник, локаль, UTM, время.
 
Email-дублирование опционально: включается наличием ключа в env, отсутствие ключа не должно ломать отправку.
 
Персональные данные не логировать в проде.
 
## Жёсткие правила
 
1. **Работаем по этапам.** Выполняй ТОЛЬКО указанный в задаче этап. Не начинай следующий, не рефактори чужие файлы «заодно». Проблему за рамками этапа — опиши в конце ответа, не чини.
2. **Никакого lorem ipsum и выдуманных фактов.** Тексты из `content/source/`. Нет данных (цена, длина, оттенок, программа курса, условия опта) — ставь `TODO_CLIENT` и перечисляй такие места в конце ответа. Не придумывай цены, характеристики волос, отзывы и условия сотрудничества.
3. **Никаких новых зависимостей** без явного разрешения в задаче. Сначала спроси.
4. **Все тексты интерфейса — через i18n**, складывай в `messages/ru.json` с первого этапа, ещё до подключения next-intl.
5. **Мобайл-фёрст.** База — 375px. Горизонтального скролла не должно быть ни на одной ширине.
6. **Доступность:** семантика, видимый фокус, контраст ≥ 4.5:1, `alt` у всех изображений, `<label>` у полей, корректные ARIA и клавиатура в аккордеонах и модалках.
7. **Изображения только через `next/image`** с явными размерами и `sizes`.
8. **Перед завершением этапа:** `npx tsc --noEmit`, `npm run lint`, `npm run build` — все три проходят. Не отчитывайся об окончании, пока они падают.
9. **Коммиты** атомарные, conventional commits, сообщения на английском.
10. **Не используй `localStorage`** для данных, влияющих на первую отрисовку. Состояние фильтров — в URL.
## Дизайн-токены
 
Сайт строго **чёрно-бело-серый**. Акцентного цвета нет — иерархия через контраст, размер и воздух.
 
```
--color-bg:          #FFFFFF   основной фон
--color-surface:     #F6F6F6   карточки, панели
--color-surface-alt: #EDEDED   секции-разделители, hover
--color-ink:         #0A0A0A   основной текст и заливка CTA
--color-ink-strong:  #000000   заголовки
--color-ink-muted:   #6E6E6E   подписи, вторичный текст
--color-border:      #E4E4E4   линии, рамки свотчей
--color-danger:      #B42318   ТОЛЬКО ошибки валидации и «нет в наличии»
--radius:            2px
```
 
Правила монохрома:
- Никаких цветных акцентов, градиентов и цветных иконок. Иконки линейные, `currentColor`.
- Primary-кнопка — сплошная заливка `--color-ink`, белый текст. На одном экране допустима **одна** primary-кнопка, остальное — `secondary` (контур) или `ghost`.
- Свотч оттенка всегда с рамкой `1px solid --color-border`, иначе блонд пропадает на белом.
- Бейджи контурные или инверсные чёрные, не цветные.
- `--color-danger` не использовать декоративно.
- Disabled — через `--color-ink-muted` и opacity, не цветом.
Шрифты: заголовки — Cormorant Garamond; текст — Inter; для локали `ka` — Noto Serif Georgian / Noto Sans Georgian (латинские шрифты не содержат грузинских глифов, семейство переключается по локали).
 
Тёмной темы нет.
 
## Тон текстов
 
Спокойный, экспертный, без рекламных восклицаний и эмодзи. Не обещаем того, чего нет: оговорки вида «при правильной установке и уходе» из материалов клиента сохраняем — они юридически значимы.
 
Для опта тон деловой и конкретный, для обучения — поддерживающий, но без инфоцыганского пафоса («изменит вашу жизнь», «секретная методика» — запрещено).
